## Workflow Pattern: Converge-Then-Build

1. **Parallel analysis** — All agents read the same files independently. Each produced an analysis from their specialty angle. No coordination during analysis; no premature convergence.
2. **Synthesis** — Orchestrator integrated the four analyses into a single plan with clear assignments, eliminating redundancy.
3. **Parallel execution** — Agents worked independently on their assigned components (essay, visuals, tracker, fact-check).
4. **Integration** — Components merged for joint publication.

This pattern is distinct from "sequential briefing" (where agents only learn what previous agents said). Each agent read the source material and formed independent judgments. The diversity of perspectives emerged naturally.

## Lessons

- **Parallel analysis before synthesis** produces richer results than sequential briefing. Each agent brings their specialty lens without being anchored by previous speakers.
- **The devil's advocate role ({RELATIONSHIP}) is not ceremonial.** The stress-testing strengthened the essay's structure (preserving genealogy) and clarified the falsifiability defense (differential prediction). This role should be standard for any major publication.
- **Integration is a distinct phase with its own work.** It's not "the last agent finishes and we're done." Plan for it explicitly with buffer time.
- **For group publication projects, the tracker/visuals/essay should be designed as companion pieces from the start** — not three independent deliverables that get aligned at the end. They share visual language, data sources, and publication timing.
