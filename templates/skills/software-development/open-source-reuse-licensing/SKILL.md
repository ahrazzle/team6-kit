# Open-Source Reuse & Licensing

Class-level discipline for pulling third-party open-source code/assets into a project without contaminating your license. Proven while evaluating OpMon/Tuxemon as a "launchpad" for {CLIENT} (a MIT plugin on the {CLIENT} framework); the island pattern also anchors the T-001 open-core product shape (free tier + paid vertical packs).

## When to Use

- User suggests reusing an open-source project ("use X as a launchpad / base / starter")
- Pulling sprites, audio, tilesets, or engines from a repo into your own build
- Building an open-core product where free community assets and paid original content coexist
- Any third-party asset entering a build that may ship commercially

## First verdict: engine vs assets (verify, don't trust README claims)

- **Engines are usually NOT forkable across stacks.** A game engine in Godot/GDScript or Python/Pygame cannot be "launched from" inside a TypeScript canvas plugin — adopting it is a REWRITE that fights your architecture. Reuse the assets + design language; build the engine yourself.
- **Assets are the real reusable layer** — sprites, tilesets, backgrounds, type icons often carry share-alike licenses that CAN legally ship beside permissive code IF kept as a distinct island.
- Read license files directly and cross-check via the GitHub API; never rely on another team's audit or a repo's self-description alone.

## The Asset-Layer Island (structural, load-bearing)

"Own directory + own LICENSE" is necessary but NOT sufficient. The boundary only survives if no code path mixes layers at AUTHORING time:

1. **Separate namespace** — borrowed assets live under `assets/<license>/` (e.g. `assets/ccbysa/`); paid/original content never references that namespace.
2. **Hard build assertion** — a build-time check that paid/original content references ZERO files from the borrowed namespace. A convention someone can break with one import is not a boundary.
3. **Per-file attribution ledger** — manifest with source repo + author + license PER FILE, hash-verified (files on disk == ledger rows). Generate with a script (`generate-manifest.py` style), never by hand. Audio entries carry extra columns (exact PCM duration, design BPM, vet status) and are generated by a sibling script (`generate-tracks.py`); the vet flag makes "exclude on doubt" STRUCTURAL — unvetted assets are excluded by default until a human flips the flag.
4. **Exclude build artifacts** — engine import metadata (`.import`, `.godot`, `.meta`) is not content; skip at pull time.
5. **Per-artist contamination traps** — in a per-file mosaic, the non-commercial assets often trace to ONE artist (Tuxemon: all 12 NC traps were Oniwanbashu). Exclude that artist's name at pull time — one contaminated file makes the whole pack non-commercial by contamination.
6. **Derivatives inherit share-alike** — any {CLIENT} repainted from a CC-BY-SA original stays CC-BY-SA. A free starter pack can use them; PAID packs must be original art (or a separate license buy).

## Provenance must be FILLABLE — license validity is not enough

A share-alike license obligates attribution; if the author's identity did not survive the source repo, the obligation is UNFILLABLE and the asset is unusable even though the license text is valid. Observed failure (OpMon-Data audio, all 3 tracks): no credits file, zero metadata tags in the `.ogg` files, and git history squashed to a single restructure commit — the composer never survived. Under the room's own "inspect at pull, exclude on doubt" rule, doubt was present and exclusion applied. Checks BEFORE accepting any share-alike asset:

- Read the repo's credits/attribution file — absence for that asset class is a red flag.
- `ffprobe -v error -show_entries format_tags` — empty tags mean no author claim anywhere.
- Inspect git history for the file (`git log --follow` / commits API) — if squashed away, identity is unrecoverable.
- If the asset's name maps onto a known franchise track (`wildbattle`, `route14`), remix risk is undetectable from the audit side — count that as doubt.
- On failure, flip `vet` to **`exclude-provenance`**, NOT `pending-ears` — this is unrecoverable, not awaiting a human. Set `ship: false` so no build path can include it; keep the file dev/test-only.

## CC0 stopgap sourcing (when the borrowed lane dies on provenance)

CC0 with NAMED authors is the replacement lane. OpenGameArt rules: the ITEM page is evidence, the collection/search page is not — open the individual item page, read its license field, and check the Copyright/Attribution notice for a real name (e.g. "Ted Kerr (Wolfgang_)"). Prefer `.ogg` native (matches the manifest pipeline), note direct file URLs, and record "CC0 per OGA page" as the attribution line. Tempo/BPM is NOT on OGA pages — measure after pull. One edge: an old page may show CC0 while comments reference a BY-SA era — re-read at pull time.

## Public release: two distribution surfaces, two leak rules

A public repo + GH Pages is two surfaces with different leak properties, needing different guards:

- **Git history is PERMANENT** — a leak there is unrecoverable (survives force-push and shallow-clone edges). Excluded files (`*.ogg` under `test-audio/`, etc.) must be gitignored BEFORE the first push — a file that never enters history cannot be resurrected. Gate the push with a pre-push audit = excluded-file sweep + ledger-vs-disk diff, ideally as a pre-commit hook, not a manual ritual.
- **The served site only ships what the build emits** — `ship: false` in the manifest already guards it, but the served bytes are what the user reviews: verify live-served bytes == canonical bundle (cache-busting meta + curl grep on the live URL).
- **License boundary must be visible to visitors, not just build scripts:** root `LICENSE` (MIT) + `assets/<license>/LICENSE` (share-alike) + the attribution ledger, all committed — GitHub shows license badges per repo from root.

## The reusable-interface abstraction

Abstract the borrowed asset's STYLE into your own schema (e.g. pixel-art frame-count grammar → your own animation schema keyed by archetype × size), never reference the source's file format directly. Engine and generator then stay independent of any one asset source — swap the art, keep the interface.

## Audio: the determinism + IP double bind (rhythm games)

Borrowed compositions carry the highest IP-remix risk AND, in a rhythm game, must be session-deterministic. Keep both questions in ONE document: a track manifest with canonical BPM + beat-grid per file; note timing derives from the manifest, never audio playback position. Mark test audio UNVETTED and keep it out of ship paths. Full rule + drift probe: `rhythm-game-development` skill.

## Web/UI design-source ingestion (the COPY/REFERENCE gate)

When the user feeds a BATCH of design/component links (libraries, icon sets, checklists, galleries), classify EVERY source at vet time into one of two buckets — never ambiguous:

- **COPY (shippable)** — license-checked, proof-gated on a real surface, cache-busted per asset doctrine. License bar applies strictly: what we may copy verbatim.
- **REFERENCE (learn-from)** — no ship constraint; animation demos, checklists, galleries, prompt libraries. Blocking these on license is a FALSE NEGATIVE — they need no copy rights. But: anything copied FROM an index/gallery inherits the SOURCE design system's own license, never the index's.

Gate order (locked): **source vet → absorb/classify → proof on one live surface → live.** The proof gate is mandatory before any absorbed source counts as live — a batch absorbed without proof is an unproven overlay (the ui-ux-pro-max lesson: broad skill-driven refresh regressed tuned work; keep absorbed sources scoped to single-decision/component-level use on mature surfaces).

Vetting rules that emerged from two link batches ({CLIENT}):

- **Pin-pass = verify the LICENSE FILE at repo head, not the README claim.** "MIT family" inferred from sibling repos FAILED against the actual repo (Kinetics had no LICENSE file → all rights reserved). Every source flagged `(verify)` gets its license TEXT checked at the pinned path before it ships; a README-stated "LICENSE — MIT" with no file is a weaker author grant, documented as such.
- **Record a provenance trail, not just the final verdict.** License-status corrections (COPY/"MIT family" → REFERENCE/"unlicensed") are logged DATED with "superseded-by-explicit" so the next reader sees the correction history.
- **Repo default ≠ every directory.** coss/ui's repo is AGPLv3 but its `/ui/` directory is MIT — only the explicitly-licensed subset can be pulled. Check per-directory licenses.
- **Licenses can carry caps.** Nucleo: 250 icons/project, 100 max in templates/themes/OSS, copyright notice required, no resale. Carry caps verbatim in the catalog.
- **Trademark caveat:** brand logos inside icon sets are governed by trademark, not the set's license — an MIT icon set does NOT license the X/Meta glyph for branding.
- **One canonical home per verdict.** The vet file is canonical; the catalog/mirror carries a pointer + the same flags. Never let the mirror drift (verify on disk after folds).

## Verifying

- Files on disk count == attribution ledger rows count (exact match, recount per class).
- Manifest entries hash-match the files.
- Grep paid/original content build config for references into the borrowed namespace — must be zero.
- Vendor copies: sparse-checkout into `vendor/<repo>/` keeps the source of truth clean and diffable.
